# Workflows

## Setup

```bash
npm install        # dependencies (package-lock.json is committed)
npx expo start     # same as npm start; press i / a / w for iOS / Android / web
```

Requirements: Node ≥ 22.13 (Expo SDK 57 minimum). The Expo CLI ships with the `expo` package — always invoke it as `npx expo ...`, no global install.

## Commands (real, from package.json)

| Task | Command |
|---|---|
| Start Expo dev server | `npm start` / `npx expo start` |
| Start + open Android | `npm run android` |
| Start + open iOS | `npm run ios` |
| Start + open web | `npm run web` |
| Typecheck | `npx tsc --noEmit` |

## Lint / Format / Tests

- **No ESLint or Prettier config is committed.** If asked to lint, say it is not configured instead of inventing rules. (When adding: `npx expo lint`, then commit the config.)
- **No test runner configured** (no jest / jest-expo). No tests exist.
- `npx tsc --noEmit` is the repo's only automated check — run it after every change.

## Environment Variables

**None used.** No `.env` files and no `.env.example` exist. When introducing them:

- Client-visible values must be prefixed `EXPO_PUBLIC_` (Expo inlines them at build/serve time).
- Secrets must never use `EXPO_PUBLIC_*`, never go in `app.json`, and never be committed — client bundles are public.
- Commit a `.env.example` containing keys only (no values), and update this doc.

## Security Practices

- Keystores/profiles are gitignored and must never be committed: `*.jks`, `*.p8`, `*.p12`, `*.key`, `*.mobileprovision`, `*.pem`.
- `/ios` and `/android` output folders are gitignored (generated by prebuild).
- `.expo/` local state is gitignored.
- No secrets currently exist in `app.json` or source — keep it that way.

## Task Templates

### Add or change a screen
1. Write `src/screens/<Name>Screen.tsx` per the pattern in [coding-standards.md](coding-standards.md).
2. Wire it in `App.tsx`.
3. `npx tsc --noEmit` → `npx expo start` → smoke-test on one platform.

### Add a native/Expo dependency
1. `npx expo install <pkg>`.
2. If the package needs a config plugin, register it in `app.json` under `expo.plugins`.
3. Restart the dev server; rebuild the dev client if the package is native.

### Upgrade Expo SDK
1. Read the versioned docs and upgrade guide first: https://docs.expo.dev/versions/v57.0.0/
2. `npx expo install expo@^<target> && npx expo install --fix`
3. Update the SDK doc URL in `AGENTS.md` to the new version.
4. `npx tsc --noEmit` and smoke-test all three platforms if possible.

### Export / build
No EAS config or build profiles exist yet. When first needed: `npx eas-cli build --profile production` after adding an `eas.json` (and never commit the credentials it manages).
